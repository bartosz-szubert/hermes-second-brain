# Decision log

Every decision that shaped the project, with the alternatives that were rejected and why — kept like a lightweight set of architecture decision records. Each entry has an ID, an area and a status; a decision that was later revised or superseded stays in the log and points to the one that replaced it.

**Areas:** Process · Security · Agent · Model · Knowledge base · Operations · Publication. **Statuses:** Active · Revised → · Superseded → · Ended · Planned · Under review · Done.

## Decisions that shaped the project

| Decision | Why it matters |
|---|---|
| **Rebuild the agent from scratch** (D-02) instead of fixing the template install (Sep) | The template's defaults caused the [incident](../POSTMORTEM.md); a clean base with a reviewed toolset was cheaper than auditing someone else's choices |
| **Agent panels only through an SSH tunnel** (D-07) (4 Oct) | The smallest attack surface, no extra service to run |
| **The agent never holds the vault's write token** (D-28, D-39); approved batches go through a host-side script (17–19 Oct) | The most important safety property — chosen over two alternatives, see [knowledge base](knowledge-base.md#write-mechanism--a-decision-worth-showing) |
| **Model from real-task tests, usage from the database** (D-24, D-54) (12–22 Oct) | Cost and quality measured, not assumed — [model selection](model-selection.md) |
| **Skills disabled by default** (D-51) (21 Oct) | 53 bundled skills were on; each re-enabled only after reading and testing |
| **Scheduled jobs get their own reduced toolset** (D-63) (28 Oct) | Closed a gap the brief's own self-check found |
| **A missed sprint goal is reported as missed; abandoned items close as *Won't Do*** (D-69, D-70) (8 Nov) | Keeps the numbers honest — [project management](project-management.md) |
| **Backups with a key that cannot delete** (D-73) (12 Nov) | A compromised server cannot destroy its own backups |
